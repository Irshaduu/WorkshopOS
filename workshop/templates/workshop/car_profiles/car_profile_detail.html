{% comment %} GROSS PROFIT — owner only, and deliberately not highlighted. It is the labour charge (which carries no direct cost) plus the margin on both part routes, and it is BEFORE wages, rent, power and every other overhead — this workshop attributes none of those to a car, because labour is quoted whole with no hours recorded, so there is nothing to apportion by. Measured against the current data it runs ~13 points above the workshop's real margin, and that gap widens as payroll grows. Hence "Gross profit" and not "Profit": the word *gross* is the warning, and `analysis_engine.build_profit_report` remains the one true profit figure in this app. It is `None` for anyone who is not an owner, so this tile is gated on the value itself rather than on a second role check that could fall out of step with the view's. {% endcomment %} {% if car_info.gross_profit is not None %}

{% comment %} THE ANCHOR LINE: WHEN · HOW LONG · WHAT STATE · HOW MUCH. The four things a history is actually scanned for, on one line, in that order, with the money right-aligned at the end of it. They used to be spread over both lines with a REFERENCE NUMBER leading in the largest type on the row — "JB-26-130" is what the workshop reads out on the phone, not what anybody scans a list by, and it was drawn as the headline while the DATE sat in the quietest type on the row. Reading a car's history meant landing on the one string you were not looking for, four rows running. So the date leads and carries the link. The bill number is not lost, it is demoted to the detail line below with the mechanic and the mileage — the things you read once you have found the row you want. The link keeps an `aria-label` naming the card, because "12 Aug 2026" alone is thin link text out of context. {% endcomment %}
{{ bill.admitted_date|date:"d M Y" }} {% comment %} HOW LONG THE CAR WAS HERE, beside the day it arrived. Those two are one statement about time and they belong together — admitted, and then for how long. It carries a clock rather than a middot because "2 days" dropped into a run of facts reads as "2 days ago", which on an old visit is a wildly different number. The glyph is the whole disambiguation, so it is a real element and never an icon-font codepoint: a stylesheet that failed to arrive would otherwise take the meaning with it. The words come from `_time_in_workshop()`, the same function the read-only job card prints, so the two screens can never state one car's stay differently. An OPEN card reads "12 days in" and turns amber — the one row where the number is still moving, and the amber the "On the floor" badge beside it already wears. {% endcomment %} {% if bill.span %}{{ bill.span.text }}{% endif %} {% comment %} Two facts, two badges, never merged.
